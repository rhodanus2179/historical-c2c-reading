# 「聖書の歴史を旅する365日」v1.3 改修設計書

作成日：2026-08-02  
対象ブランチ：`feature/v1.3`  
対象バージョン：v1.2.1 → v1.3.0

## 1. 目的

v1.3では、毎日の通読時に生じる操作上の迷いを減らすとともに、将来の読了統計機能に必要なデータ基盤を整備する。

重点は次の3点とする。

1. 「現在読むべきDay」と「ユーザーが閲覧しているDay」を明確に区別する。
2. 読了状態に読了日時を保持できる状態形式へ移行する。
3. 誤操作、バックアップ復元、アクセシビリティに関する安全性を高める。

v1.3では統計画面自体は実装しない。曜日別・時間帯別統計、連続読了日数、活動カレンダー等は、v1.3で蓄積する読了日時を利用してv1.4以降で実装する。

## 2. 現状と課題

### 2.1 現在読むべきDayと閲覧中Dayが混同される

現行画面は、通読表や前後ボタンから過去・未来のDayを開いた場合でも、「今日の通読」「今日のメモ」と表示される。

また、自分のペースモードでは、読了操作後に「次の未読Day」が変化する一方、画面には直前に読了したDayが表示され続ける。この状態を明示する導線がない。

### 2.2 読了日時を保持していない

現行の `progress` は、Dayごとに `"completed"` または `"unread"` を保持する形式であり、いつ読了したかを判定できない。

このため、曜日別・時間帯別の傾向、連続読了日数、月間活動量等を算出できない。

### 2.3 読了操作に取消手段がない

現行は読了状態が即時に切り替わる。再度ボタンを押せば戻せるが、誤タップ直後に直感的に取り消す手段がない。

### 2.4 バックアップ復元の検証が限定的

現行はバックアップ内の `app` 名を主に確認しており、状態データの型、Day範囲、設定値、将来バージョンとの互換性等を十分には検証していない。

### 2.5 アクセシビリティ上の小課題がある

トースト通知のライブリージョン、フォームラベルと入力欄の関連付け、フォーカス表示、現在ページを示すARIA属性等を補強できる。

## 4. 用語定義

### 4.1 通読対象Day（target day）

現在の進行モードから算出される、ユーザーが次に読むことを想定したDay。

- 自分のペースモード：最初の未読Day
- カレンダーモード：開始日から算出した当日の予定Day

実装上は、現行の `currentDay()` を `targetDay()` に改称する。画面上の文言はモードに応じて次のようにする。

- 自分のペース：「次の通読」
- カレンダー：「今日の予定」

### 4.2 閲覧中Day（selected day）

ユーザーが画面上で現在開いているDay。通読表、前後ボタン、メモ一覧等から変更される。

### 4.3 一致状態

`selectedDay === targetDay()` の状態。

### 4.4 参照状態

`selectedDay !== targetDay()` の状態。過去または未来のDayを参照している状態を含む。

## 5. 機能設計

## 5.1 通読対象Dayと閲覧中Dayの分離

### 5.1.1 表示ルール

一致状態では、通読カードのラベルを進行モードに応じて表示する。

- 自分のペース：`○ 次の通読`
- カレンダー：`○ 今日の予定`
- 読了済みの場合：`✓ 読了`

参照状態では、次を表示する。

- ラベル：`閲覧中 Day N`
- 見出し：`Day Nの通読`
- メモ見出し：`Day Nのメモ`
- ボタン：`次の通読 Day Mへ` または `今日の予定 Day Mへ`

### 5.1.2 読了後の挙動

読了操作後も閲覧中Dayは自動で切り替えず、読了したDayに留まる。

自分のペースモードでは、読了によって `targetDay()` が次の未読Dayへ進むため、読了後は参照状態となる。画面上に `次の通読 Day Mへ` を表示し、ユーザーが読了結果を確認してから次へ進めるようにする。

最終Dayまで読了済みの場合は、通読対象をDay 365として扱い、ボタン文言を `通読完了` とする。無効な遷移ボタンは表示しない。

### 5.1.3 前後移動ボタン

- Day 1では前へボタンを無効化する。
- Day 365では次へボタンを無効化する。
- 現行のようにDay 1またはDay 365を指す有効ボタンとして残さない。
- `disabled` 属性と視覚上の無効状態を一致させる。

## 5.2 状態スキーマv4

### 5.2.1 保存形式

`state.version` を `4` とする。

`progress` は、読了済みDayだけを保持する。未読Dayのキーは存在させない。

```json
{
  "version": 4,
  "settings": {
    "startDate": "2026-07-01",
    "mode": "pace",
    "theme": "system",
    "fontSize": 16,
    "translation": "si"
  },
  "progress": {
    "42": {
      "status": "completed",
      "completedAt": "2026-08-02T09:15:30.000Z",
      "utcOffsetMinutes": 540
    },
    "43": {
      "status": "completed",
      "completedAt": null,
      "utcOffsetMinutes": null
    }
  },
  "notes": {},
  "selectedDay": 42
}
```

### 5.2.2 フィールド定義

| フィールド | 型 | 内容 |
|---|---|---|
| `status` | string | v1.3では `completed` のみ |
| `completedAt` | string / null | UTCのISO 8601日時。旧データは不明のため `null` |
| `utcOffsetMinutes` | number / null | 読了時点のUTCオフセット。日本標準時は `540` |

`utcOffsetMinutes` は `-new Date().getTimezoneOffset()` で取得する。

読了日時をローカル時刻へ戻す際は、`completedAt` の時刻に `utcOffsetMinutes` を加算し、UTC系getterで年月日・曜日・時刻を取得する。これにより、将来別のタイムゾーンでアプリを開いても、読了時点の現地曜日・時刻を再現できる。

### 5.2.3 状態アクセス関数

UIから状態形式を直接参照せず、次の関数を経由する。

- `isCompleted(day)`
- `getCompletion(day)`
- `markCompleted(day, now = new Date())`
- `markUnread(day)`
- `completedDays()`
- `doneCount()`

これにより、v1.4で統計処理を追加する際の変更範囲を限定する。

## 5.3 状態移行

### 5.3.1 v3からv4への変換

起動時に読み込んだ状態がv3以前またはバージョンなしの場合、次の規則で正規化する。

| 旧値 | v4での扱い |
|---|---|
| `"completed"` | `status: "completed"`, 日時は `null` |
| `"unread"` | キーを削除 |
| 不明な文字列 | キーを削除 |
| 不正なDay番号 | キーを削除 |

既存の読了済みDayについて、移行時点の現在日時を読了日時として設定してはならない。過去の読了時刻を捏造すると、将来の統計が不正確になるためである。

### 5.3.2 正規化対象

起動時およびバックアップ復元時に、次を正規化する。

- `selectedDay`：1～365に丸める
- `settings.fontSize`：14～20に丸める
- `settings.mode`：`pace` または `calendar`
- `settings.theme`：`system`、`light`、`dark`
- `settings.startDate`：有効な `YYYY-MM-DD`
- `notes`：Day 1～365の文字列のみ保持
- `progress`：Day 1～365の有効な読了レコードのみ保持

### 5.3.3 移行の保存

移行・正規化後の状態が読み込み前と異なる場合、v4形式で直ちに `localStorage` へ保存する。

移行処理は複数回実行しても結果が変わらない冪等な処理とする。

## 5.4 読了／未読切替のUndo

### 5.4.1 基本動作

読了ボタンを押した際は、確認ダイアログを表示せず即時反映する。

反映後、トーストに次を表示する。

- メッセージ：`Day Nを読了にしました`
- 操作：`元に戻す`

未読に戻した場合も同様に、元の読了レコードを復元できるようにする。

### 5.4.2 Undo保持方式

Undo情報はメモリ上に1件だけ保持し、localStorageには保存しない。

```js
{
  day: 42,
  previousRecord: null,
  nextRecord: {
    status: "completed",
    completedAt: "...",
    utcOffsetMinutes: 540
  }
}
```

- `previousRecord` が `null` の場合、Undo時は該当キーを削除する。
- 読了済みから未読へ変更した場合、Undo時は元のレコードを復元する。
- 新しい読了状態変更を行った場合、前のUndo情報を置き換える。
- Undo可能時間は5秒を標準とする。
- Undo実行時は状態を保存し、現在画面を再描画する。

## 5.5 トースト設計

現行の文字列専用トーストを、任意のアクションボタンを持てる形式へ拡張する。

```js
toast(message, {
  actionLabel: "元に戻す",
  onAction: undo,
  duration: 5000
});
```

要件：

- 通常通知は従来どおり約1.8秒で閉じる。
- Undo付き通知は5秒表示する。
- 新しい通知を出す際は、既存タイマーを解除する。
- アクション実行後はトーストを閉じる。
- トースト本体に `role="status"`、`aria-live="polite"`、`aria-atomic="true"` を設定する。
- ボタンへキーボードフォーカスを強制移動しない。

## 5.6 バックアップと復元

### 5.6.1 エクスポート形式

バックアップ形式に `formatVersion` を追加する。

```json
{
  "app": "BibleHistoryReading",
  "formatVersion": 2,
  "exportedAt": "2026-08-02T09:30:00.000Z",
  "data": {}
}
```

`data.version` は状態スキーマのバージョンを表し、`formatVersion` はバックアップ外装形式のバージョンを表す。

### 5.6.2 互換性

次のバックアップを受け入れる。

- v1.2.1以前の `formatVersion` なし形式
- `formatVersion: 1`
- `formatVersion: 2`

現在より新しい `formatVersion` または状態バージョンは拒否し、「新しいバージョンのアプリで作成された可能性があります」と表示する。

### 5.6.3 検証

復元前に次を確認する。

- JSONとして解析できる
- `app === "BibleHistoryReading"`
- `data` がオブジェクト
- サポート対象のバックアップ形式
- 状態バージョンが現在以下

その後、起動時と同じ正規化処理を適用する。不正な個別項目は安全な既定値へ置換するが、バックアップ全体の識別に失敗した場合は復元しない。

### 5.6.4 インポート前ロールバック

有効なバックアップを適用する直前に、現在の正規化済み状態を別キーへ1件保存する。

- 通常状態：`bible-history-reader-v1`
- 復元前状態：`bible-history-reader-v1-pre-import`

復元前状態がある場合、設定画面に `復元前の状態に戻す` ボタンを表示する。

ロールバック実行時は、現在状態と復元前状態を入れ替える。これにより、操作をもう一度行えば再度戻せる。

全データ初期化時は、通常状態と復元前状態の両方を削除する。

## 5.7 アクセシビリティ

### 5.7.1 ナビゲーション

- 選択中のナビゲーションボタンへ `aria-current="page"` を付与する。
- 非選択ボタンからは属性を削除する。
- すべてのボタンに必要に応じて `type="button"` を明示する。

### 5.7.2 フォーム

- すべての設定項目で `label[for]` と入力欄の `id` を対応させる。
- 通読表検索欄、メモ検索欄に視覚上またはスクリーンリーダー向けラベルを設ける。
- 文字サイズスライダーに現在値を示すテキストを追加する。

### 5.7.3 フォーカス表示

`button`、`input`、`select`、`textarea`、ファイル選択ラベルに統一的な `:focus-visible` 表示を追加する。

フォーカスリングは背景色にかかわらず判別でき、既存の配色テーマを損なわないものとする。

### 5.7.4 状態表現

読了状態を色だけで表現せず、従来どおりチェック記号と文言を併用する。

## 5.8 DOM参照の明示化

現行コードの一部は、要素の `id` がグローバル変数として公開されるブラウザ挙動に依存している。

v1.3では、使用する要素を `document.getElementById()` または描画範囲内の `querySelector()` で明示的に取得する。

例：

```js
const sidebar = document.getElementById("sidebar");
const mobileNav = document.getElementById("mobileNav");
const headerProgress = document.getElementById("headerProgress");
```

HTML文字列内のインライン `onclick` も廃止し、`data-*` 属性とイベントリスナーで処理する。

## 8. 実装方針

- フレームワーク、ビルド工程、外部依存は追加しない。
- `index.html` の直接起動とGitHub Pagesの双方を維持する。
- localStorageの通常キーは変更しない。
- 既存の進捗、メモ、設定を失わない。
- 状態形式を直接参照する条件式をUIに散在させない。
- JavaScriptは可読性のある複数行形式へ整形する。
- 整形のみの変更と機能変更は、可能な限りコミットを分ける。
- `innerHTML` にユーザー入力を挿入する場合は、引き続き `esc()` を使用する。

## 9. テスト設計

### 9.1 状態移行

1. v1.2.1形式で複数Dayを読了済みにする。
2. v1.3を起動する。
3. 読了数、メモ、設定、選択Dayが維持されることを確認する。
4. 旧読了レコードの `completedAt` が `null` であることを確認する。
5. 再読み込み後も同じ状態であり、移行が重複しないことを確認する。

### 9.2 新規読了

1. 未読Dayを読了にする。
2. `completedAt` が有効なISO日時であることを確認する。
3. 日本標準時環境で `utcOffsetMinutes` が `540` であることを確認する。
4. 再読み込み後も読了状態が維持されることを確認する。

### 9.3 Undo

1. 未読Dayを読了にし、5秒以内にUndoする。
2. 未読へ戻ることを確認する。
3. 読了済みDayを未読にし、Undoする。
4. 元の読了日時が保持されたまま復元されることを確認する。
5. 5秒経過後にUndo操作が消えることを確認する。

### 9.4 通読対象と閲覧中Day

1. 通読対象以外のDayを通読表から開く。
2. 「閲覧中」と現在の通読対象へ戻るボタンが表示されることを確認する。
3. 戻るボタンで通読対象へ移動することを確認する。
4. 自分のペースモードで通読対象を読了し、次の通読Dayへの導線が表示されることを確認する。
5. カレンダーモードでも文言が「今日の予定」となることを確認する。

### 9.5 境界値

- Day 1の前へボタンが無効
- Day 365の次へボタンが無効
- 全365日読了時に不正な次Dayが表示されない
- `selectedDay` が0、366、文字列の場合に安全に補正される

### 9.6 バックアップ

- v1.2.1形式を復元できる
- v1.3形式を復元できる
- 別アプリ形式を拒否する
- 壊れたJSONを拒否する
- 将来バージョンを拒否する
- 不正な個別値を安全に正規化する
- 復元後に「復元前の状態に戻す」が機能する
- 全データ初期化でロールバック状態も削除される

### 9.7 表示・操作

- Windows 11 Chrome
- iPhone相当幅
- Android相当幅
- ライト／ダークモード
- 文字サイズ14／20

## 10. 受入基準

次のすべてを満たした場合、v1.3改修を完了とする。

1. 既存の進捗、メモ、設定が失われずにv4へ移行する。
2. 新規の読了記録に読了日時とUTCオフセットが保存される。
3. 旧読了記録に架空の読了日時が付与されない。
4. 通読対象Dayと閲覧中Dayを画面上で判別できる。
5. 読了／未読変更を5秒以内にUndoできる。
6. バックアップ復元前の状態へ戻せる。
7. 不正または将来形式のバックアップを安全に拒否できる。
8. Day 1／365の前後移動が正しく無効化される。
9. 主要操作をキーボードで実行でき、フォーカスを視認できる。
10. `index.html` の直接起動とGitHub Pages公開の双方で動作する。
11. READMEおよび画面上のバージョンがv1.3.0に一致する。

## 11. v1.4への接続

v1.3の状態スキーマを利用し、v1.4では次を候補とする。

- 曜日別読了回数
- 時間帯別読了回数
- 平均読了時刻
- 現在・最長の連続読了日数
- 月間活動カレンダー
- 予定Dayとの差

`completedAt: null` の旧読了記録は総読了数には含めるが、曜日・時間帯・連続日数等の日時依存統計からは除外し、「日時不明の旧記録」として件数を表示する。
